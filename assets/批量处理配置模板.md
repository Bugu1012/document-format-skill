# 批量处理配置模板

批量修订多个 .docx 文件时，使用以下配置模板定义修订规则。

## YAML 配置

```yaml
# 批量修订配置
batch_revision:
  # 输入输出
  input_dir: "./待修订/"
  output_dir: "./已修订/"
  # 原文件不被修改（修订结果另存到 output_dir），无需备份

  # 适用规则
  rule_set: "gbt_9704_2012"  # 或 "custom"
  custom_overrides:
    line_spacing_pt: 28.95  # 如本机关使用其他行距，在此覆盖
    body_font: "仿宋_GB2312"
    title_font: "方正小标宋简体"

  # 修订范围
  scope:
    page_layout: true      # 页面设置（纸张、页边距）
    body_format: true      # 正文字体、字号、行距、缩进
    title_format: true     # 标题字体、字号、对齐
    heading_format: true   # 各级标题字体
    page_number: false     # 页码（需 XML 操作，默认关闭）
    header_footer: false   # 页眉页脚（默认关闭）

  # 排除规则
  exclude:
    skip_image_paragraphs: true   # 跳过含图片的段落
    skip_tables: false            # 是否跳过表格内段落
    skip_paragraphs_with_styles:  # 跳过使用特定样式的段落
      - "TOC Heading"
      - "Header"
      - "Footer"

  # 输出选项
  output:
    generate_report: true         # 每个文件生成修订报告
    report_format: "markdown"     # markdown / json
    overwrite: false              # false = 另存到 output_dir
    suffix: "_修订"               # 另存时的文件名后缀

  # 验证
  verification:
    content_hash: true            # 修订前后文字哈希验证
    paragraph_count: true         # 段落数验证
    re_diagnose: true             # 修订后重新诊断
```

## 使用方式

1. 复制本模板到项目目录，修改 `input_dir` 和 `output_dir`。
2. 根据本机关制度调整 `custom_overrides`。
3. 根据修订需求调整 `scope` 中的开关。
4. 执行批量修订脚本（由技能生成）。
5. 检查输出目录中的修订报告。

## 错误处理

- 单个文件修订失败不中断批量流程。
- 失败文件记录到 `batch_errors.log`。
- 内容哈希验证失败的文件不输出到 output_dir，记录到错误日志。
- 批量完成后输出汇总统计。

## 注意事项

- 批量处理前建议先用单个文件测试修订效果。
- 含大量图片的文档修订速度较慢（需逐段判断是否含图片）。
- 页码修订（`page_number: true`）需要 XML 直接操作，建议在单文件模式下先验证。
